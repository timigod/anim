## Terms you will encounter

Some names come from statistics; others are names used in Anim's commands and
files. The guides use ordinary language where possible and retain the exact
names when you need to find a field or diagnose a problem.

| Term | Meaning in Anim |
| --- | --- |
| Event-based model, or EBM | A model that estimates the order in which events, such as biomarkers becoming abnormal, occur. |
| Event order | A proposed sequence of events. It is an estimate from the model, not a directly observed disease timeline. |
| Stage | A position in the model's event sequence. It does not establish a person's onset date or prognosis. |
| Worker | A separate program that runs your chosen model and exchanges requests and results with Anim. |
| Adapter | The code that translates between your model's interface and Anim's worker format. |
| Backend | The model implementation used by the worker, such as pysaebm. |
| Candidate | One planned analysis, with specified data, preprocessing, model settings, and other declared choices. It stays in the plan even if it cannot run. |
| Universe | A candidate whose inputs have been successfully prepared for execution, together with its planned sampling chains. An unprepared candidate has no universe. |
| Analysis plan | The complete set of analyses chosen before the audit runs. |
| Central order | One order selected using the model's stated method. Comparing central orders does not measure the uncertainty within each fit. |
| Chain and retained samples | A sequence of states generated by a sampling algorithm and the states kept for analysis. Anim checks whether those samples support the requested comparison. |
| Random seed | A recorded starting value for a random-number generator. Reproducing a run also depends on its data, software, settings, and environment. |
| Capability | An operation or result the worker says it supports, such as fitting a model or returning stage probabilities. |
| Conformance check | A software test of whether the worker follows Anim's format and supplies the outputs it says it supports. |
| Pinning | Recording the exact software files and versions so later changes can be detected. |
| Hash, digest, or checksum | A value calculated from bytes to detect whether they changed. A hash alone does not prove where a file came from or make data anonymous. |
| Provenance | The recorded inputs, software, settings, and processing steps behind a result. |
| Artifact | A saved file produced by a run, such as a report, result array, or configuration record. |
| Receipt | A machine-readable record of a check or operation. Its stated status and scope matter; the existence of the file alone does not mean the check passed. |
| Schema | The required structure and allowed values of a file or message. |
| Null or no-signal control | Generated data designed to lack the disease-order structure being tested. Such controls help assess whether a method can produce apparent structure without that signal. |
| Not assessable | Anim lacks the results or conditions needed to answer the particular question. It does not mean the answer is “no difference.” |

## Technical specifications

The [technical reference guide](technical-reference-guide.md) explains which
specifications describe current interfaces and which preserve historical records.
The files under [docs/spec](../spec) define the exact calculations, file formats,
and acceptance rules. They are references for implementing or reviewing Anim.
They use versioned field names, mathematical definitions, and words such as
`MUST` and `MUST NOT` to specify requirements. These requirements are distinct
from evidence that a particular model or study has met them.

The [worker protocol](../spec/adapter-protocol.md),
[result formats](../spec/canonical-data-and-result-schema.md), and
[metrics and uncertainty definitions](../spec/metrics-and-uncertainty.md) are
useful when a practical guide does not answer an implementation question.
The [security threat model](../security/threat-model.md) describes the risks and
limits of the software's protections.

Internal names such as `PlanningAuthority` and `PreparationTransaction` identify
objects used by the implementation to check that a result belongs to a valid
run. They do not refer to scientific, clinical, or institutional approval.
Use the CLI and worker SDK unless a developer guide explicitly describes
another supported interface.
